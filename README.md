# OSRS Путь

Личный трекер прогресса в Old School RuneScape (бесплатная версия) по гайду `osrs-guide.md`:
63 шага в 6 этапах, 12 навыков, цели по этапам, квесты, справка и плагины RuneLite.
Без сервера и аккаунтов. Есть программа для Windows (exe), а в браузере работает офлайн
и ставится на экран «Домой» iPhone.

## Программа для ПК

Готовые файлы — на странице [Releases](https://github.com/bexaf3163/OSRS/releases/latest):

- **`OSRS-Put-Setup-<версия>.exe`** — установщик: ярлык на рабочем столе и в «Пуске», удаляется
  через «Установленные приложения».
- **`OSRS-Put-<версия>-portable.exe`** — без установки, просто запустить.

Обе версии хранят прогресс в одном месте — `%APPDATA%\OSRS Путь` — и видят его одинаково.
Браузер и телефон хранят свой прогресс отдельно; переносить — через экспорт и импорт (ниже).

Exe не подписан сертификатом, поэтому при первом запуске Windows SmartScreen может показать
«Windows защитила ваш компьютер» → «Подробнее» → «Выполнить в любом случае».

Ссылки на вики открываются в обычном браузере. Меню скрыто — показывается по Alt;
масштаб — Ctrl + / Ctrl −, обновить — Ctrl+R.

## Запуск

Нужен Node 22.18 или новее (скрипты данных написаны на TypeScript и запускаются самим Node).

```bash
npm install
npm run dev
```

Откроется `http://localhost:5173`.

| Команда | Что делает |
|---|---|
| `npm run dev` | Локальная разработка |
| `npm run build` | Проверка типов и сборка в `dist/` |
| `npm run preview` | Открыть собранную версию (`http://localhost:4173`) |
| `npm test` | Юнит-тесты (Vitest) |
| `npm run check-data` | Проверка данных и сверка `src/data` с гайдом |
| `npm run parse-guide` | Перенос `osrs-guide.md` → `src/data/*.json` |
| `npm run icons` | Перерисовать иконки в `public/` |
| `npm run desktop` | Собрать и открыть программу для ПК (Electron) |
| `npm run dist:win` | Собрать exe: установщик и переносную версию в `release/` |

## Выпуск новой версии

1. Поднять `version` в `package.json` (её видно внизу «Настроек»).
2. `npm run check-data`, `npm test`, `npm run dist:win`.
3. Закоммитить, запушить и выложить exe:

```bash
gh release create v1.2.0 release/OSRS-Put-Setup-1.2.0.exe release/OSRS-Put-1.2.0-portable.exe --title "OSRS Путь 1.2.0" --notes "Что изменилось"
```

При каждом пуше GitHub Actions прогоняет `check-data`, тесты и сборку (`.github/workflows/checks.yml`).

## Как выложить веб-версию

`npm run build` собирает статическую папку `dist/`. Все пути в ней относительные, поэтому
она работает из любого адреса: корня домена или подпапки.

**Netlify.** Перетащи папку `dist` на [app.netlify.com/drop](https://app.netlify.com/drop).

**GitHub Pages.** На приватном репозитории Pages работает только на платном тарифе GitHub.
Для публичного репозитория опубликуй `dist`, например так:

```bash
npm run build
npx gh-pages -d dist
```

и в настройках репозитория (Settings → Pages) выбери ветку `gh-pages`.

**На iPhone:** открой адрес в Safari → «Поделиться» → «На экран „Домой“». После первого
открытия приложение работает без интернета. Новая версия подхватывается при следующем запуске
после того, как телефон увидел её онлайн.

## Перенос прогресса между устройствами

Прогресс хранится только в браузере (`localStorage`). Синхронизации нет, перенос — файлом:

1. На старом устройстве: шестерёнка → **Экспорт прогресса** (на iPhone ещё есть **Поделиться файлом** —
   удобно отправить через AirDrop или сохранить в «Файлы»).
2. На новом устройстве: шестерёнка → **Импорт прогресса** → выбрать файл → **Заменить**.

Импорт заменяет прогресс целиком; сразу после замены его можно отменить в появившемся сообщении.

Важно для iPhone: приложение с экрана «Домой» хранит данные **отдельно** от вкладки Safari.
Прогресс, отмеченный во вкладке, в приложении не появится — переносить тоже файлом.

## Обновление данных после изменения гайда

`osrs-guide.md` — единственный источник данных. В рантайме markdown не читается:

1. Поправь `osrs-guide.md`.
2. `npm run parse-guide` — разбор и проверка; если есть ошибки, файлы не перезаписываются.
3. `npm run check-data` и `npm test`.

Что проверяется: 63 шага от `S1-01` до `S6-07` с типом, названием и «Готово, когда»;
12 навыков с планом прокачки; зависимости ссылаются на существующие шаги; очки квестов
в сумме 46 и совпадают с текстом «Награды» каждого шага и со строкой «Очки квестов»
в «Целях по этапам»; формула опыта совпадает с таблицей гайда. `check-data` вдобавок
ловит ситуацию, когда гайд поменяли, а `parse-guide` не запустили.

Про «Где»: у 10 шагов (S3-12, S4-04, S4-05, S4-07, S4-08, S5-09, S5-10, S6-02, S6-06, S6-07)
в гайде этой строки нет. Проверка выводит их предупреждением — ничего не дописано.

### Что взято не из гайда

Всё собрано в начале `scripts/guide-parser.ts`:

- **очки квестов за шаги** — таблица из задания (гайд пишет их только текстом, проверка сверяет);
- **соответствие строк «Целей по этапам» и разделов навыков** (Атака, Сила, Защита → ближний бой `ME`);
- **слова в названиях шагов** («Рыбалка до 20») → цели по уровням, по ним шаг подсказывает строку плана.

## Как считается

- **«Что делать сейчас»** — первый по порядку незакрытый шаг, у которого закрыты все зависимости
  и хватает очков квестов.
- **Закрытый шаг** — сделанный или пропущенный. Пропустить можно только необязательный S3-07
  (Shield of Arrav); очков он тогда не даёт, и максимум становится 45 из 46.
- **Строка плана прокачки** — по введённому уровню: диапазон «15–30» включает 15, но не 30.
  Ближний бой — по отстающему из атаки, силы и защиты.
- **Цель «50–60»** считается достигнутой с 50.
- **Опыт** — стандартная формула OSRS.

## Устройство

```
osrs-guide.md          источник данных
scripts/               parse-guide, check-data, разбор и проверки, иконки
src/data/              JSON из гайда (генерируется, в репозитории)
src/lib/               прогресс, «что сейчас», очки, опыт, диапазоны, поиск
src/components/        шаг, этап, карточка «сейчас», таблица, поиск, значки
src/pages/             Путь, Навыки, Навык, Цели, Квесты, Справка, Настройки
tests/                 юнит-тесты
electron/main.cjs      окно программы для ПК
vite.config.ts         сборка и генерация service worker (без workbox)
```

Зависимости: React, Vite, TypeScript, Vitest, для exe — Electron и electron-builder.
