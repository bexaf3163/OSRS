# OSRS «Путь» — карта проекта: что есть, где лежит, как связано

> Файл написан так, чтобы его можно было целиком бросить в другой чат и предложить, что добавить или исправить. Версия проекта: **2.20.0** (протокол моста 5). Репозиторий: https://github.com/bexaf3163/OSRS. Язык интерфейса и текстов — русский.
> Опись составлена по исходникам; пометка **[не в игре]** — в живой игре не проверялось, только тесты, браузер и имитация плагина.

---

## 1. Что это

Программа-спутник для Old School RuneScape (F2P и Members). Ведёт игрока по готовому маршруту (9 этапов, 69 шагов: 54 для F2P и 15 для подписки), следит за его прогрессом через плагин RuneLite и сама готовит к каждому шагу: проверяет уровни, снаряжение, сумку, банк, монеты, квесты, ведёт стрелкой в игре.

Из двух частей:

| Часть | Что это | Где |
|---|---|---|
| **Программа для ПК** | React 19 + Vite + TypeScript в оболочке Electron; один переносной exe `OSRS-Put-<версия>-portable.exe`, без установки и без сервера | `src/`, `electron/` |
| **Плагин RuneLite «OSRS Path Bridge»** | Java 17, Gradle; оверлеи в игре, HTTP-мост `127.0.0.1:38282`; jar кладётся внутрь exe, программа сама запускает RuneLite с плагином | `runelite-bridge/` |

Прогресс хранится у игрока на диске (папка `OSRS-Put-data` рядом с exe, файл `progress.json` + localStorage окна). Аккаунтов, сервера и веб-версии нет (убраны в 2.7.0 по просьбе владельца, не возвращать).

## 2. Принципы (на них держится вся логика)

1. **Неизвестно ≠ нет.** Любое значение: «есть / нет / неизвестно». Нет данных из игры — программа не утверждает, что предмета нет (`Known<T>` в `src/lib/playerState.ts`).
2. **Не выдумывать данные.** Время — только по замерам; цены — с биржи или «из базы проекта» с пометкой; DPS и опыт — по формулам вики. Нет значения — «неизвестно».
3. **Один источник правды.** Готовность, закупки, подготовка, стрелка читают одно состояние игрока и один движок (`readinessEngine.ts`); параллельных копий не делать.
4. **Живое → ручное → неизвестное.** Приоритет источника количества предмета.
5. **Ничего не покупается автоматически.** Программа рекомендует, ведёт, подсвечивает — решение за игроком.
6. **Лишнее прячем, не удаляем.** Режим «Дзен» по умолчанию, «Инспектор» показывает всё.
7. **Экран игры — «куда кликнуть», программа — аналитика.** В игре список «Что нужно» и HUD видны всегда («Умное проявление» в плагине есть, но по умолчанию выключено — владелец не хочет прятать информацию в игре).
8. **Данные из вики, а не из головы.** Скрипты `build-*` собирают данные с OSRS Wiki; этапы квестов — из исходников Quest Helper.
9. **Тесты не ослаблять.** Падение — сначала разбор, что оно защищает.
10. Убрано по просьбе владельца и не возвращается: веб-версия и телефон, установщик NSIS, метки путевых точек на земле, строка импорта Bank Tags (подсветка нужного в банке осталась).

## 3. Как всё связано (поток данных)

```
 RuneLite (игра)
   └─ плагин OSRS Path Bridge (Java)
        ├─ читает: уровни, опыт, сумка, надето, банк, монеты, положение, квесты, переменные квестов (varp/varbit)
        ├─ HTTP 127.0.0.1:38282  +  поток событий (SSE) ─────────────┐
        └─ рисует: стрелку, HUD, список «Что нужно», радар, подсветку │
                                                                      ▼
 Electron (главный процесс)  electron/runelite-bridge.cjs  — единственный, кто ходит на localhost (без CORS)
                                                                      │  preload.cjs → окно
                                                                      ▼
 Окно (React)   src/bridge.tsx  — состояние связи, события, автоотметка шагов
        ├─ src/store.tsx            прогресс (localStorage + файл progress.json), профили, отмена
        ├─ src/playerStateContext   единое состояние игрока + журнал ресурсов
        ├─ src/readinessContext     движок готовности (память расчётов)
        └─ страницы и карточки шага (src/pages, src/components)
```

Обратно в игру программа шлёт: активный шаг (`POST /active-step`), временную цель стрелки (`/nav-target`), оптовый список (`/shopping-plan`), предметы этапа для банка (`/bank-tags`), совет по снаряжению (`/gear-hint`), сброс (`/clear`).

Что приходит от плагина в `/status` и событиях: `inGame`, `activeStepId`, `stats`, `xp`, `questsDone`, `player`, `pos`, `shortestPath`, `navTarget`, `equipment`, `inventory`, `coins`, `bankCoins`, `carriedValue`, `bankValue`, `inventorySlots`, `weight`, `protocol`, `pluginVersion`. События: `STATUS`, `STATS`, `XP`, `QUESTS`, `OWNED`, `GEAR`, `PACING`, `STEP_AUTO_COMPLETED`, `NAV_SET`, `NAV_DONE`, `MOVED` (смерть или скачок на 20+ клеток).

### Карточка шага (то, что на экране «Путь»)
- **Единый статус** вместо стопки плашек: «🟢 Готов к выходу · Начать шаг» / «🟡 Требуется подготовка (N пунктов) · Исправить · Подробнее»; в «Подробнее» вкладки: подготовка, снаряжение, еда, путь и игра, прокачка и варианты. `components/StepStatus.tsx`.
- **Дзен / Инспектор:** `components/DensityToggle.tsx`, флаг `inspector` в `lib/features.ts`. Дзен — шаг, статус, что делать, «Сделано», критичные предупреждения; остальное в «Подробнее о шаге».
- **Готовность:** уровни, квесты, предметы, монеты, режим; действия «Добрать Crafting», «К банку», «В закупки». `lib/readiness.ts`, `readinessEngine.ts`, `components/ReadinessPanel.tsx`.
- **Маршрут подготовки и автоочередь:** что сделать до выхода по порядку (до 3 вложенных объездов, без циклов), сама ведёт стрелку, сама возвращает к шагу. `lib/prepRoute.ts`, `prepQueue.ts`, `usePrep.ts`, `components/PrepRoute.tsx`.
- **План подготовки «Что нужно»:** одно решение — где вещь (надето/сумка/банк/нет/неизвестно), что делать, важность (критично/важно/улучшение), срок (сейчас/заодно/по ходу/позже), почему, расходники (хватает/мало), готовность в %, место в сумке, вес и бег. `lib/prepPlan.ts` (строится поверх одной ходки `lib/oneTrip.ts`), показ — `components/OneTripCard.tsx`.
- **Вес и бег:** `lib/weight.ts` (формула OSRS Wiki «Run energy»), `data/weights.json` (`npm run build-weights`), вес и занятые ячейки из игры — события GEAR.
- **Режим восстановления** после смерти/телепорта: `lib/recovery.ts`, `lib/useRecoveryTracker.ts`, событие MOVED, плагин `MoveDetector`; баннер в `OneTripCard.tsx` (`RecoveryBanner`).
- **Откуда взять предмет:** банк → сумка → бесплатно рядом → магазин → биржа. `lib/sourceRouter.ts`.
- **Чем качать** (61 способ, по уровню, режиму, предметам, стилю игры спокойно/эффективно). `lib/trainingRouter.ts`, `data/trainingMethods.json`, `lib/playStyle.ts`.
- **Быстрые варианты по статам** (Varrock Teleport при Magic 25, каноэ при WC 12…): `lib/branching.ts`, `components/BranchSuggestions.tsx`.
- **Апгрейд инструмента:** «⚡ Скоростной апгрейд» (Bronze → Steel axe у Bob). `services/gearUpgradeRouter.ts`, `components/UpgradePrompt.tsx`, `data/toolProgression.json`.
- **Бой:** «Сильнее в бою» (`GearPrompt`), «Еда на бой» (`FoodAdvice`, `data/threats.json`), «Что носить для магии/стрельбы» (`StyleGear`, `data/styleGear.json`), темп боя.
- **Деньги:** «Цель шага» (`MoneyGoal`), «Как добрать деньги» (`MoneyPlan`, `data/moneyMaking.json`), «Магия до цели» (`MagicPlan`, `lib/magicPlan.ts`).
- **Карта и навигация:** карта шага (`StepMap`), карта мира на весь экран (`WorldMapModal`, Leaflet грузится отдельным куском), «Как добраться» с положением из игры (`TravelPlan`, `lib/travel.ts`, `data/transport.json`), единая цель навигации (`lib/navigation.ts`), места из досье вики (`PlaceMap`, `services/locationResolver.ts`, `data/majorLocations.json`, 126 мест).
- **Показать в игре:** шаг уходит в плагин (`InGamePanel`, `NavigateButton`, `services/runeliteBridge.ts`); значок «● Активно в RuneLite».
- **Проверка вылета** (`PreflightPanel`, `lib/checklist.ts`) — что из предметов шага в сумке.
- **Инспектор вики** (`WikiDrawer`, `services/wikiService.ts`, `wikiApi.ts`): досье предмета/NPC (202 предмета в локальной базе `f2p-items.json`), цены биржи — живые.
- **Журнал ресурсов** (`lib/ledger.ts`, `ledgerStore.ts`): добыча, покупки, продажи, награды; хранится между сеансами (до 30 дней, на персонажа и профиль); оценка добычи по свежим ценам биржи (`lib/priceBook.ts`), монеты и оценка — всегда раздельно.
- **Профили персонажей**, чужой персонаж не пишет в профиль (`lib/profiles.ts`, `components/ProfileBanner.tsx`); автоотметка шагов из игры (квест, уровень, предметы: `lib/triggers.ts`, `bridge.tsx`).

## 5. Плагин RuneLite (папка `runelite-bridge/`)

**Оверлеи в игре:**
- Стрелка к цели (большая, вращается по камере, состояния «Рядом»/«Рядом совсем»): `OsrsPathArrowOverlay`, `ArrowGeometry`.
- Микро-HUD: код шага, цель, расстояние, темп, здоровье, подготовка: `OsrsPathHudOverlay`. **Компактный** (настройка `hudLean`, по умолчанию вкл.): пока на экране список «Что нужно», название шага, цель, расстояние и «Сумка» из HUD убираются, плашка остаётся только с предупреждением (опасность, здоровье, действие, темп, совет по снаряжению) — `OsrsPathHudOverlay.lean`, видимость списка — `GuideList.shown`.
- Список «Что нужно» (предметы шага, где взять, точки шага, клик — стрелка к месту): `OsrsPathGuideOverlay`, `GuideList`, `GuideMouse`, `StepGuide`.
- Проверка вылета у банка, подсветка предметов в сумке и банке: `InventoryCheckOverlay`, `OsrsPathItemOverlay`, `Checklist`.
- Подсветка NPC, объектов, клеток, вариантов диалога: `OsrsPathWorldOverlay`, `OsrsPathWidgetOverlay`.
- Радар опасности (зоны из `dangerZones.json`, 4 зоны раннего F2P): `DangerRadar`, `OsrsPathDangerOverlay`.
- Подсказка на Grand Exchange (оптовый список): `GrandExchangeHelperOverlay`, `ShoppingPlan`.
- Боковая панель «OSRS Путь»: `OsrsPathPanel`.
- Темп прокачки и боя: `PacingTracker`, `PacingSet`.
- Этапы квестов: по переменной квеста (varp/varbit) плагин определяет этап и шаги с клетками (данные `src/data/questStages.json`, 32 квеста, из Quest Helper). Текущий шаг ведёт `StageTracker` (чистая логика, каждый тик): по положению (`StepGuide.advance`), по предметам — `has` (добыл → засчитано, шаги без условий перед ним тоже; и если предмет ушёл дальше — следующий шаг его сдал), `need` (сдал: предмет ушёл в 12 клетках от точки; не сдал — дальше шага не уйти, список возвращает и объясняет). **Вперёд кликом пропустить нельзя**: «✓ Сделано — дальше» есть только у шагов, которые игра сама не покажет (следующий на том же месте или без места: `needsManualStep`, 111 из 663). «◀ Назад» — просмотр на 45 с, потом снова по фактам; «▶ К текущему шагу» — сразу. Все 250 этапов проходятся в тесте `QuestStageWalkTest` без тупиков. Стрелка идёт за шагом (`OsrsPathBridgePlugin.trackStageCursor/followStage`). Короткий текст строки — поле `s` (505 строк, проверка `stages-short`), запасное сокращение — `ShortText` (плагин) / `lib/shortText.ts` (программа).
- Автоотметка шага в игре: `AutoCompletionManager`.
- «Умное проявление» (по умолчанию **выключено**): `SmartView`.
- **Протокол 6 (2.22):** один снимок состояния `POST /prep-plan` вместо пяти запросов (`/active-step`, `/shopping-plan`, `/bank-tags`, `/gear-hint`, план). Программа: `lib/prepEnvelope.ts` (сборка, `planPayload`, `nextSeq`), `PrepSync.tsx` (план активного шага), `bridge.tsx` (`snapshot`, `setPrepPart`, `flushSnapshot`; плагин <6 — старые запросы). Плагин: `PrepEnvelope`/`PrepPlan` (проверка по частям, `seq` против запоздавших), `OsrsPathBridgePlugin.onPrepPlan/applySnapshot` (за один проход клиентского потока), `GuideList` рисует процент, «мало», «Не бери сейчас», вес, сумку, режим восстановления. Контракт — `runelite-bridge/src/test/resources/prep-snapshots.json` (пишет `tests/prepEnvelope.test.ts`).
- Запуск: `OsrsPathLauncher` (+ `electron/runelite-launcher.cjs`).

**Настройки плагина** (`OsrsPathBridgeConfig`, раздел «Помощник в игре» и др.): `port`, `hintArrow`, `worldMapMarker`, `highlightColor`, `completionSound`, `smartOverlays`, `showHud`, `showGuide`, `guideCollapsed`, `hudOpacity`, `hudLarge`, `showChecklist`, `bigArrow`, `arrowSize`, `useShortestPath`, `showGeHelper`, `shareStats`, `autoNavigation`, `upgradeRouter`, `bankTagsHelper`, `bankHighlight`, `dangerRadar`, `dangerSound`, `smartPacing`, `hudPacing`, `hudHealth`, `stageFollow`.

**Мост:** `BridgeServer.java` — HTTP `/status`, `/active-step`, `/shopping-plan`, `/nav-target`, `/bank-tags`, `/gear-hint`, `/clear`, `/events` (SSE); отвечает только на `127.0.0.1`, любой `Origin` получает 403. Версия плагина `PLUGIN_VERSION` обязана совпадать с `package.json`.

## 9. Что не доделано / не проверено

- **В живой игре не проверено** всё, что сделано с 2.16.0: этапы квестов и стрелка за шагом, список «Что нужно» после правок, автоочередь подготовки, «Умное проявление», журнал за несколько дней. Готовые чеклисты: `AUDIT_REPORT.md` (разделы «Живая проверка»).
- **Снаряжение Members** не заведено (нужны проверенные ID и требования).
- Оценка апгрейда по сэкономленному времени не считается (нет замеров).
- В игре «Что нужно» пока показывает прежний список: план подготовки (важность, сроки, вес, режим восстановления) виден только в программе.
- Радар знает 4 зоны; координаты по вики.
- Квесты без этапов: Dragon Slayer (S5-xx), Shield of Arrav. Без quickSteps: S6-01, S6-03, S7-04, S8-03, S8-04.
- Способы прокачки: до ~70 уровня и 20 навыков; Hunter/Construction/Slayer — только по плану гайда. Авто-стрелка к месту — у 40 из 61 способа.
- Шаги «верни/отдай» без условия `need` (S1-03, S3-03, S3-04…) защищены только общим правилом смены этапа.
- Ленивая загрузка JSON сознательно не делается (локальная программа; бандл ~1,1 МБ).
- Построчная вычитка всего русского текста не проводилась (автоправила есть).

## 10. Идеи для развития (что можно предложить)

Из `AUDIT_REPORT.md` («Что можно добавить») и сверки:
1. Живая проверка и сбор замечаний по игре — самый ценный следующий шаг.
2. Единая «сборка» под этап (бой / инструменты / еда / зелья / телепорты / квестовое / деньги) с одной кнопкой.
3. Members-данные: Dragon axe/pickaxe, броня и оружие подписки — по проверенным данным вики.
4. Этапы для Dragon Slayer и Shield of Arrav; `need` для остальных шагов «верни/отдай».
5. Полоса подготовки в HUD игры; перерисовка оформления списка и HUD (владелец считает его «не красивым»).
6. Больше зон радара, замер радиусов в игре.
7. Журнал ресурсов: график по дням, экспорт.
8. Способы прокачки на высоких уровнях и для Hunter/Construction/Slayer.
9. Автообновление программы (сейчас невозможно: репозиторий приватный).
10. Компонентные тесты (jsdom) вместо одного только прогона в браузере.

## 11. Как пользоваться этим файлом в другом чате

Приложи этот файл и скажи, что хочешь: «придумай, что добавить в раздел X», «найди слабые места в Y», «перепиши экран Z». Чтобы изменение не сломало основу, держи в голове §2 (принципы) и §3 (поток данных): новая функция должна читать одно состояние игрока (`playerState.ts`), показывать «неизвестно», а не «нет», и проходить `npm test`, `npm run check-data` и `npm run test:ui`.
