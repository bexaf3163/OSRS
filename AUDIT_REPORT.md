## Architecture

- Один источник истины для прогресса — `StoreProvider` (`src/store.tsx`), для моста — `BridgeProvider`
  (`src/bridge.tsx`). Активный шаг в игру уходит одним путём: `syncActiveStep` → `/active-step`. Временная
  цель (место из досье, магазин апгрейда) — отдельный `/nav-target`, плагин держит её поверх шага и сам
  возвращается к шагу (`NAV_DONE`: пришёл, купил, снял).
- Подключение к событиям одно: единственный `EventSource` в `runeliteBridge.ts` с переподключением по
  нарастающей задержке, закрывается при размонтировании. Повторных потоков нет.
- Координаты мест живут в одном словаре `majorLocations.json` (126 мест, собирается `npm run build-locations`
  из вики, вручную не правится); по предметам координаты не прописаны — их находит `locationResolver`
  (точка появления из вики → словарь → статья вики → нестрогое совпадение → поиск по вики).
- Чистая логика отделена от компонентов, чтобы тестироваться без DOM: `lib/places.ts`, `lib/pacing.ts`,
  `lib/bankTags.ts`, `services/gearUpgradeRouter.ts`.
- Мёртвого кода не найдено: каждый модуль в `src/components`, `src/lib`, `src/services`, `src/pages`
  импортируется. Циклических зависимостей между сервисами нет.

## Persistence

- Прогресс: `normalizeProgress` разбирает любые старые сохранения (тесты `progress.test.ts`, `migration`):
  недостающие поля получают значения по умолчанию, неизвестные шаги отбрасываются с подсчётом, выполненное
  не сбрасывается. Новое поле `upgradeDismissedForSteps` необязательное; старые сохранения его не имеют.
- В программе для ПК прогресс дублируется в файл `progress.json` (запись через временный файл); при старте
  берётся более свежий из файла и localStorage.

  (`null`, `[]`, `"x"`, обрывок JSON, число, объект с чужими типами) × 4 страницы (Путь, шаг, список GE,
  настройки). До исправления падал `shopping-range = null` (см. Fixed #2).

- Настройки помощника (`osrs-put:features`) разбираются поштучно: незнакомое и битое → включено.

## RuneLite Bridge

- Слушает только `127.0.0.1` (`InetAddress.getLoopbackAddress()`), порт 38282. Host — только локальный
  (защита от DNS rebinding), Origin — только свой; POST требует заголовок `X-OSRS-Path: 1`; тело до 64 КБ.
- Неверный JSON и неверные значения → 400 с текстом; выключенная в настройках функция → 409 с объяснением.
  Проверено через собранный exe: `/nav-target` с `x: -1` → 400 «неверные координаты».
- Жизненный цикл: `stop()` закрывает все SSE-потоки, сервер, пингер и пул потоков; `shutDown()` плагина
  снимает все 8 оверлеев и чистит временную цель, радар, отметки банка. Порт занят → предупреждение в лог,
  плагин работает без моста, без падения.
- Новые потоки получают последнее состояние (GEAR, PACING и прежние события) сразу при подключении.
- Java-тесты: 63 (BridgeServer 15, PacingTracker 11, DangerRadar 8, Checklist 9, AutoCompletion 7,
  Navigation 7, RouteTargets 3, ShoppingPlan 3) — все проходят.

## Performance

- Оверлеи не ходят в сеть и в вики. Граница опасной зоны считается один раз при загрузке (`ring()`),
  рисуется только в пределах 20 клеток; расстояния — квадраты, без `Math.sqrt`.
- NPC для контуров ищутся один раз при входе в зону предупреждения, дальше — по событиям появления и
  исчезновения, не каждый кадр. Ячейка товара в магазине запоминается.
- Звук — один раз на вход в зону (гистерезис 3 клетки против дребезга на границе), не каждый кадр.
- Отчёты в приложение (снаряжение, темп) уходят только при изменении и не чаще раза за тик.
