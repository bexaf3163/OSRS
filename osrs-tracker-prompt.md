# Промт для Claude Code: трекер прогресса OSRS

Положи рядом с этим промтом файл `osrs-guide.md` (в корень пустой папки проекта), открой папку в Claude Code и вставь текст ниже целиком.

---

Собери небольшое веб-приложение «OSRS Путь» — личный трекер прогресса в Old School RuneScape (бесплатная версия). Весь контент берётся из файла `osrs-guide.md` в корне проекта. Интерфейс на русском языке.

## Главное правило про данные

- `osrs-guide.md` — единственный источник правды. Ничего не придумывай и не дописывай от себя: ни шагов, ни уровней, ни мест, ни наград.
- Один раз разбери markdown и перенеси содержимое в структурированные файлы `src/data/*.json` (или `.ts`). В рантайме markdown не парси.
- Сохраняй английские названия предметов, квестов и мест в скобках так, как они написаны в гайде (например «Удочка нахлыстом (Fly fishing rod)»): по ним ищут в игре и на вики.
- После переноса проверь себя и выведи в консоль итог проверки:
  - шагов ровно 63 (коды от `S1-01` до `S6-07`), у каждого есть тип, название, «Где», «Готово, когда»;
  - навыков 12, у каждого есть таблица «План прокачки» с кодами диапазонов (`WC-1`, `FI-2` и т. д.);
  - все зависимости из таблицы «Все шаги и зависимости» ссылаются на существующие коды;
  - сумма очков квестов равна 46 (таблица ниже).

## Стек

- Vite + React + TypeScript. Без бэкенда, без аккаунтов.
- Прогресс хранится в `localStorage`. Плюс кнопки «Экспорт прогресса» (скачать JSON) и «Импорт прогресса» (загрузить JSON), чтобы переносить прогресс между ноутбуком и телефоном.
- Сделай приложение PWA (манифест и service worker), чтобы его можно было добавить на главный экран iPhone и открывать без интернета.
- Минимум зависимостей. Никаких тяжёлых UI-библиотек; стили — CSS-модули или обычный CSS с переменными.

## Модель данных

```ts
type StepType = 'quest' | 'skill' | 'gear' | 'prep';

interface Step {
  id: string;            // "S3-05"
  stage: 1 | 2 | 3 | 4 | 5 | 6;
  type: StepType;
  title: string;         // "Vampyre Slayer"
  where?: string;        // «Где»
  bring?: string;        // «Взять»
  how?: string;          // «Как»
  tips?: string[];       // «Совет», «Заодно», «Опасно», «Внимание», «Нужно», «Зачем»
  reward?: string;       // «Награда»
  doneWhen: string;      // «Готово, когда»
  requires: string[];    // коды шагов из таблицы зависимостей
  minQp?: number;        // «QP ≥ 12» и т. п. из таблицы зависимостей
  qp?: number;           // сколько очков квестов даёт (таблица ниже)
  optional?: boolean;    // S3-07 Shield of Arrav
}

interface Stage {
  id: number; title: string; start: string; time?: string; qpAtEnd?: number; summary: string; // «Итог этапа»
}

interface SkillRange { code: string; from: number; to: number | null; what: string; where?: string; amount?: string; notes?: string; }
interface Skill { id: string; name: string; nameEn: string; intro: string; tables: Table[]; ranges: SkillRange[]; sections: Section[]; }
```

Прогресс пользователя:

```ts
interface Progress {
```

## Экраны

Навигация — вкладки: на телефоне нижняя панель, на широком экране — верхняя или боковая.

### 1. Путь (главная)

- **Шапка прогресса:** общий процент выполненных шагов, очки квестов «N / 46», текущий этап.
- **Карточка «Что делать сейчас»** — самый заметный элемент экрана. Это первый по порядку невыполненный и непропущенный шаг, у которого выполнены все зависимости и хватает очков квестов. Показывает код, тип, название, «Где», «Взять» и «Готово, когда», кнопку «Сделано» и ссылку «Подробнее». Если по этому шагу есть подходящая строка прокачки навыка (по введённому уровню), покажи её подсказкой.
- **Этапы 1–6** — сворачиваемые блоки. В заголовке: название, «x / y шагов», тонкая полоса прогресса. Текущий этап раскрыт, завершённые свёрнуты и отмечены.
- **Шаг в списке:** чекбокс, код, значок типа, название. По клику раскрывается подробно: все поля шага, награда, заметка пользователя (редактируемое поле).
- Шаг с невыполненными зависимостями отмечать можно, но он показывается приглушённым с подписью «Сначала: S2-06, S2-04».
- Необязательный шаг (S3-07) можно пометить «Пропущено» — он считается закрытым для зависимостей и процента.
- Внизу этапа — «Итог этапа» из гайда.
- Отмена последнего действия: после отметки короткий тост «Отмечено S2-05 · Отменить».

### 2. Навыки

- Сетка из 12 карточек навыков: название, текущий уровень (редактируемое число), цель текущего этапа из таблицы «Цели по этапам», текущий код диапазона.
- Экран навыка: вводные строки, все таблицы из гайда (отрисованные как таблицы), «План прокачки» с подсвеченной строкой по текущему уровню, «Полезно знать», «Частые вопросы».
- Вверху экрана навыка — калькулятор: текущий уровень → целевой уровень → сколько опыта осталось (по таблице «Сколько опыта нужно до уровня» или стандартной формуле опыта OSRS).
- Отдельная вкладка внутри «Навыков» или блок сверху — «Как устроена прокачка» и таблица опыта по уровням.

### 3. Цели

- Таблица «Цели по этапам» (навык × этап). Ячейки подсвечиваются: достигнуто (уровень пользователя ≥ цели) / не достигнуто. Строка «Очки квестов» считается из отметок.

### 4. Квесты

- Список всех квестов из шагов типа quest плюс Learning the Ropes (отмечен сделанным): название, этап, очки, статус. Фильтр «все / сделанные / доступные / заблокированные». Клик ведёт к шагу на главной.

### 5. Справка

Подразделы из гайда, каждый — отдельная страница или раскрывающаяся секция:
- Вход и настройка
- Бесплатная версия или подписка
- Как навыки кормят друг друга (mermaid-схему из гайда нарисуй простым SVG или списком «→»; не тяни mermaid ради одной схемы)
- Если не знаешь, что делать
- Плагины RuneLite (все таблицы плагинов, с фильтром по «Встроенный / Hub»)
- Советы и безопасность
- Ссылки на вики (кликабельные, открываются в новой вкладке)

### 6. Настройки (иконка шестерёнки в шапке)

- Экспорт и импорт прогресса (JSON).
- Сброс прогресса с подтверждением.
- Переключатель темы: светлая / тёмная / системная.

### Поиск

Глобальный поиск в шапке (или по `/`): ищет по кодам шагов, названиям, предметам и навыкам, результаты ведут к шагу или разделу.

## Дизайн

- Минимализм: много воздуха, один акцентный цвет, никаких теней-«облаков» и градиентов. Тонкие границы 1px, скругления 10–12px.
- Палитра: тёплый нейтральный фон, почти чёрный текст; акцент — приглушённое золото (в духе OSRS, но спокойно, например `#B8892E`). Цвет «выполнено» — спокойный зелёный. Всё через CSS-переменные, с полноценной тёмной темой.
- Шрифт: системный (`system-ui`) или Inter; код шага — моноширинный.
- Значки типов шагов — простые одноцветные SVG: квест, навык, снаряжение, подготовка.
- Анимации короткие (150–200 мс): раскрытие этапа, отметка чекбокса.
- Адаптивность: удобно на экране 6,3" (iPhone) и на ноутбуке 14". Кнопки не меньше 44px по высоте на телефоне.
- Доступность: нормальный контраст, фокус с клавиатуры, чекбоксы — настоящие `input` с подписями.

## Тесты и проверка

- Юнит-тесты (Vitest) на: выбор «Что делать сейчас», подсчёт очков квестов, подсчёт опыта между уровнями, поиск строки диапазона по уровню, экспорт/импорт прогресса.
- Скрипт `npm run check-data`, который повторяет проверки из раздела «Главное правило про данные».
- В конце запусти `npm run build`, `npm test`, `npm run check-data` и убедись, что всё проходит.

## Результат

- `npm install` и `npm run dev` запускают приложение локально.
- `npm run build` собирает статическую версию, которую можно выложить на GitHub Pages или Netlify и открыть с телефона.
- Коротко опиши в `README.md`: как запустить, как выложить, как перенести прогресс между устройствами, как обновить данные после изменения `osrs-guide.md`.

Сначала покажи план (структуру данных и экраны), дождись моего «ок», потом пиши код.
